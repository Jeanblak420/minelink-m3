## 6. Super-admin → create-company E2E

### Static trace of the flow (verified end-to-end in source)

Frontend ([`register_company_screen.dart`](../lib/features/super_admin/screens/register_company_screen.dart#L42-L154)):

1. UI gated by `currentPlatformRoleProvider` and `platformAdminSettingsProvider.childCanRegisterCompanies`.
2. Form fields: company name, WhatsApp, org type (mineSupplier / buyer / transporter), CEO first / last (optional), owner email (validated), optional temporary password (≥ 8 chars when supplied).
3. On submit, invokes `SupabaseConfig.client.functions.invoke('super-admin-create-company', body: {...})`.
4. On success: shows `AlertDialog` with company name, owner email, temporary password, "Copy message" + "Open company (token & seats)" actions.
5. On open → `context.go('/super-admin/organization/$companyId')`.
6. Invalidates `organizationsProvider` and `organizationsGroupedProvider` so the new company shows up immediately in `/super-admin/organizations`.

Backend ([`supabase/functions/super-admin-create-company/index.ts`](../supabase/functions/super-admin-create-company/index.ts)):

1. CORS preflight handled; POST only.
2. Auth header required; caller resolved via `caller.auth.getUser(token)`.
3. Looks up `profiles.platform_role` for the caller — must be `superGlobalSerialAdminMain` or `superGlobalSerialAdminMainChild`, else `403`.
4. For child admins, additionally checks `platform_admin_settings.id='main'`: `child_super_admin_user_id` must match the caller AND `child_can_register_companies` must be true, else `403`.
5. Validates payload server-side (same fields as the form).
6. Creates auth user via `admin.auth.admin.createUser` with `email_confirm: true` and metadata `{ user_type: "company", display_name: companyName }`.
7. Updates `profiles` for the new user: `user_type = 'company'`, `display_name`, `must_change_password = true`.
8. Inserts `companies` row with `user_id`, `company_name`, `whatsapp_number`, `org_type`, `ceo_first_name`, `ceo_last_name`.
9. Inserts an `audit_logs` row with `action_type = 'COMPANY_REGISTERED_BY_PLATFORM'`.
10. Returns `{ success, company_id, company_name, org_type, owner_email, temporary_password }`.
11. On any failure after `createUser`, rolls back via `admin.auth.admin.deleteUser`.

Migrations supporting this (file list):

- `supabase/migrations/20260510180000_add_platform_roles_and_company_access.sql` (platform roles)
- `supabase/migrations/20260510181500_create_super_admin_tables.sql` (audit_logs, platform_admin_settings)
- `supabase/migrations/20260510205000_super_admin_write_rpcs_and_hardening.sql`
- `supabase/migrations/20260510230000_platform_register_company_and_password_gate.sql` (mandatory password change)

The static trace is **internally consistent**: the form, edge function, RLS migrations, and the router's `_cachedMustChangePassword` gate all line up.

## 7. New-company sign-in E2E

### Static trace of the flow

1. User navigates `/login` and enters the owner email + temporary password emitted by §6.
2. `LoginForm._submit()` calls `authStateProvider.notifier.signIn(email, password)` ([`lib/features/auth/widgets/login_form.dart:28-47`](../lib/features/auth/widgets/login_form.dart#L28)).
3. Supabase auth state change fires → `_GoRouterRefreshStream` notifies router.
4. Router redirect refreshes profile gate: `must_change_password = true` (set by the edge function) → returns `/mandatory-password-change` ([`lib/core/routing/app_router.dart:142-144` and `159-169`](../lib/core/routing/app_router.dart#L142)).
5. `MandatoryPasswordChangeScreen._submit()` calls `auth.updateUser(...)`, then sets `profiles.must_change_password = false`, then `AppRouter.clearProfileGateCache()`, then `auth.refreshSession()` ([`mandatory_password_change_screen.dart:34-74`](../lib/features/auth/screens/mandatory_password_change_screen.dart#L34)).

## 9. Windows vs Mobile parity sweep

- `lib/features/profile/screens/profile_screen.dart` — `PlatformUtils.isWeb` chooses between `_webImageBytes` (web) and `_imageFile` (mobile/desktop) for the profile-photo upload. Windows desktop and Android both take the `_imageFile` path. **No parity gap.**
